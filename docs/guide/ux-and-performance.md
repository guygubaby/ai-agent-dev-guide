# 体验与性能

## UI 必须展示真实状态

| 状态 | 推荐反馈 |
| --- | --- |
| submitted | 立即显示“正在读取上下文” |
| reasoning | 可折叠显示，增量合并到同一个区域 |
| tool running | 显示工具名称和目标摘要 |
| tool success/error | 明确成功或失败，不只依赖颜色 |
| streaming | 允许停止，不锁住历史消息滚动 |

回答结束后，通用 Loading 必须立即消失。不要用循环文案掩盖工具是否成功。

## 滚动规则

- 用户接近底部时，新内容自动跟随。
- 用户向上阅读时，不抢滚动，并显示“回到底部”。
- 用户主动发送消息时，平滑滚到底部。
- `ResizeObserver` 处理图片和折叠卡片带来的高度变化。
- 尊重 `prefers-reduced-motion`。

## 语言

固定 UI 跟随应用语言；模型回复优先跟随本轮用户消息语言。用户用中文提问，即使界面是英文，也应回复中文。

## 性能重点

1. Context 分页、限长和按需读取。
2. 使用 `activeTools`，不在每一步发送全部工具 schema。
3. 裁剪旧 reasoning 和过期 tool results。
4. 设置最大步骤数、输出 token 和取消能力。
5. 按帧合并流式文本、Markdown 渲染与自动滚动。
6. 对可选解析器、欢迎动效等重依赖使用动态导入。

建议记录首个可见状态、首 token、Agent 步数、工具耗时/成功率和撤销率；日志中不要保留原始敏感内容。
