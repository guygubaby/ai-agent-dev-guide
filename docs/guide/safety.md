# 安全边界

## API Key

任何被浏览器使用的共享 Key 都可以被用户看到。不要用代码混淆、加密 LocalStorage 或环境变量名来宣称安全。

| 方案 | 适合场景 |
| --- | --- |
| BYOK | 用户使用自己的模型额度 |
| 短期凭据 | 已有认证系统能签发受限 token |
| 薄模型代理 | 共享 Key、限流、审计或跨租户权限 |

## 工具权限

System prompt 中的“不要越权”只是提示。每次工具执行仍要由应用检查身份、权限、目标和版本。

## 危险操作

删除、覆盖、发布、付款等动作不能在第一次 tool call 时执行：

1. 冻结动作类型、目标 ID、版本和影响摘要。
2. UI 展示明确的确认与取消按钮。
3. 用户确认时再次检查权限、目标和版本。
4. 确认过期或状态变化时重新询问。

确认必须绑定具体目标，不能复用一句模糊的“确定”。

## 不可信内容

模型回复、上传文件、网页内容和外部 API 数据都不可信：

- Markdown 转 HTML 后使用 DOMPurify 白名单净化。
- 持久化富文本使用独立、更严格的业务白名单。
- URL 限制为允许协议。
- 不执行模型生成的 JavaScript、脚本标签或任意代码。
- 不把敏感 Context 写入日志和错误追踪。

:::danger
纯前端工具与当前用户拥有相同的浏览器权限。缩小工具能力，比继续加长 Prompt 更有效。
:::
