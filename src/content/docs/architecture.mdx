## 分层架构

```text
┌────────────────────────────────────────────────────────────┐
│ Vue 应用                                                   │
│                                                            │
│  Chat UI ─ useChat ─ DirectChatTransport ─ ToolLoopAgent   │
│                                               │            │
│                         instructions + tool registry       │
│                                │                │          │
│                 read tools     │                │ write tools
│                      ▼          │                ▼          │
│             context adapter     │          action adapter   │
│             Store / DOM / API   │       transaction / undo  │
└─────────────────────────────────┼───────────────────────────┘
                                  │ HTTPS stream
                                  ▼
                     OpenAI-compatible endpoint
```

各层只负责一件事：

| 层 | 职责 | 不应该做什么 |
| --- | --- | --- |
| Chat UI | 输入、流式 parts、工具状态、确认和滚动 | 直接拼业务 JSON |
| Agent | instructions、模型、步骤上限、工具选择 | 绕过工具修改 Store |
| Context adapter | 把应用事实转换成精简、脱敏 DTO | 完整序列化 Store |
| Tool registry | 定义稳定能力与 Zod schema | 接受任意 path/value patch |
| Action adapter | 权限、目标重查、事务、副作用 | 相信模型参数天然正确 |
| Store / domain | 维护真正的业务状态和不变量 | 感知模型实现细节 |

## 运行时流程

<Steps>
1. **发送消息**

   `useChat.sendMessage()` 立即把 UI 置为 submitted。回答语言优先取本轮消息，无法判断时才使用界面 locale。

2. **准备调用**

   `prepareCall()` 重新读取当前页面、设计端和选择范围，生成本轮 instructions；同时裁剪过期 reasoning 和旧 tool results，应用当前 modelId 与供应商参数。

3. **开放最小工具集**

   `prepareStep()` 根据用户意图和已经调用过的 discovery tools 计算 `activeTools`。模型第一次不需要看见全部二十多个工具 schema。

4. **模型决定下一步**

   模型可以输出文本、reasoning 或一个/多个 tool calls。`ToolLoopAgent` 执行工具并把结果送入下一步，直到模型给出最终回答或触发停止条件。

5. **执行工具**

   读取工具返回事实；写入工具调用领域 Action。Action 会重新按稳定 ID 查找目标、检查权限、验证字段，再以事务方式更新状态。

6. **同步画布与 UI**

   修改后刷新 Schema/画布，按原 PC 或 Mobile 端重新绑定选中节点，标记页面未保存，并把结构化结果渲染成工具卡片。
</Steps>

## 核心创建代码

下面展示的是可迁移骨架。真实项目还需要 provider 能力探测、错误映射和业务工具实现。

```ts
import { createOpenAICompatible } from '@ai-sdk/openai-compatible'
import { DirectChatTransport, ToolLoopAgent, isStepCount } from 'ai'
import { useChat } from '@ai-sdk/vue'

const provider = createOpenAICompatible({
  name: 'company-provider',
  baseURL: config.baseUrl,
  apiKey: config.apiKey,
})

const agent = new ToolLoopAgent({
  model: provider(config.modelId),
  instructions: createSystemPrompt(initialScope),
  tools,
  stopWhen: isStepCount(12),
  maxOutputTokens: 3200,
  temperature: 0.2,
  prepareCall: ({ messages }) => ({
    instructions: createSystemPrompt(readCurrentScope()),
    messages: pruneConversation(messages),
  }),
  prepareStep: ({ steps }) => ({
    activeTools: getActiveToolNames(steps),
  }),
})

const { messages, sendMessage, status, stop, error } = useChat({
  transport: new DirectChatTransport({
    agent,
    sendReasoning: true,
  }),
})
```

<Aside type="note" title="为什么使用 DirectChatTransport">
它直接调用同一 JavaScript 进程中的 Agent，不需要自己实现 `/api/chat`。在纯前端应用中，这个“同一进程”就是浏览器；因此模型 endpoint 必须允许浏览器跨域请求，凭据也会对用户可见。
</Aside>

```text
  agent/

    reader.ts

    read-tools.ts

  ui/
    AgentPanel.vue
    AgentMessage.vue
    ToolPart.vue
    ApprovalCard.vue
    SafeMarkdown.vue
```

这些模块是依赖方向，而不只是文件分类：UI 依赖 Agent；工具依赖 Context/Action；Action 依赖业务 Store。业务 Store 不应反向依赖 AI SDK。
