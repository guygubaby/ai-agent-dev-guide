# 先理解 Agent

Agent 不是“更长的聊天 Prompt”。它是一个循环：模型读取事实、选择工具、查看执行结果，再决定是否继续。

```text
用户消息
   ↓
最新 Context
   ↓
模型选择 Tool
   ↓
应用校验并修改 State
   ↓
结果返回模型和 UI
```

## 四个核心

| 核心 | 一句话原则 |
| --- | --- |
| Context | 给模型足够完成任务的最新事实，不要完整复制应用状态 |
| Tools | 每个工具只做一件清晰、可校验的事 |
| State | 模型不能直接改状态，只能调用应用已有的 Action |
| Safety | 凭据、权限、危险操作和外部内容必须由代码保护 |

## 一次请求只做五步

1. 识别用户意图和回复语言。
2. 读取当前任务需要的 Context。
3. 只开放相关 Tools。
4. 执行工具并把结果交回模型。
5. 在 UI 中说明执行状态和最终结果。

## 纯前端是什么意思

Agent 循环、Context 读取和本地工具都运行在浏览器，不需要额外搭建聊天服务。

但浏览器无法隐藏共享 API Key。纯前端适合：

- 用户自带 Key（BYOK）。
- 短期、受限凭据。
- 明确接受 Key 可见的内部环境。

公开产品如果使用共享 Key，应增加一个很薄的模型代理；应用状态和工具依然可以留在前端。

:::tip
先做“读取并回答”，确认 Context 正确后，再加入第一个可撤销的写工具。
:::
